## Goal and agreed policy
An explicit tools: [] means no active or callable child tools under normal Pi configuration. An omitted tools value keeps existing defaults. Preserve existing non-empty allowlist behavior and the deliberate edit-implies-write rule. Do not disable configured foreground extensions, skills or MCP server startup; users may intentionally rely on their startup. No-tools is a tool-access setting, not an OS sandbox against arbitrary trusted extension code or a promise to prevent deliberate extension reactivation. Background's existing noExtensions/noSkills behavior remains unchanged. Source plus #442 and its maintainer comments are authoritative; when a brief claim conflicts, stop and report it.

## Measured pre-fix evidence (Pi 1.5.0, dev 5f2f4c8)
resolveSubagentParams retains tools: []; buildSubagentArgs omits any restriction; preflight rejects outputFile for unavailable write. With the actual foreground runSubagent and a scratch-only fake extension, local stdio MCP server and scripted loopback model, tools: [] allowed both extension_canary and mcp__local_canary__canary to execute. Actual spawnBackgroundSession with omitted or empty tools loaded neither extension nor MCP; forced canary calls returned tool-not-found, and empty tools gave zero active tools. A foreground wrapper injecting --no-tools made the direct extension/MCP canary calls fail as tool-not-found while extension startup and MCP initialization/listing still occurred. RPC snapshots for direct, codemode and deferred MCP exposure under --no-tools showed zero active/registered tools after discovery; those three snapshots did not themselves prove executed-tool behavior for every exposure mode. Scratch paths are ephemeral and NOT a required input to implementation.

- Keep foreground extensions/MCP discovery and background resource-loader settings unchanged. Do not add --no-extensions, --no-mcp, no-skills, a new dependency, or any unrelated redesign.
