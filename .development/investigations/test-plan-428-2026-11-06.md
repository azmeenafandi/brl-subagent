# Plan critique — issue #428 (`test: cover skipJsonValue`)

**Verdict: AMEND** (needs-work). Tree audited: `dev` @ `a67e9a3`, Node v24.14.1, tsx 4.23.15, vitest 5.

The plan's *target* is right and the CRAP evidence behind it is real. But as written it cannot be
executed to a defensible result: its acceptance metric is unmeasurable in this repo and contradicts
the ADR that scheduled the issue; the one mutation kill it requires is provably out of reach of the
assertions its own framing implies; its malformed-input bullet demands an oracle that does not exist
for 40% of the inputs it lists; and it never names a seam. Everything below is measured, not argued —
17 mutants of the real reader plus a 100-case matrix (`/tmp/probe428/`).

---

## Findings

### BLOCKING

**B1 — `≥90% statement coverage` is not measurable here, and contradicts ADR 0021.**
- `ls node_modules/@vitest` → `mocker`, `spy` only. No `coverage-v8`. `package.json` `scripts` has
  `typecheck`, `docs:arch`, `docs:decisions` — **no `test` and no `coverage` script**; the suite is run
  as `npx vitest run` (CONTRIBUTING.md:64) and `vitest.config.ts` declares no `coverage` block.
- `.development/decisions/0021-no-crap-gate-targeted-followups.md` §1: *"No new CI dependency"*,
  *"CI gains no coverage step"*, and names `@vitest/coverage-v8` in CI as **rejected machinery**.
  §3 adds that if coverage ever returns, *"settle the measurement's boundaries first: … statement
  coverage as a proxy for branch coverage"*. The issue's acceptance re-imports exactly that proxy.
- The implementer cannot even install it locally: the worktree guard blocks package-manager installs
  through a symlinked `node_modules` (`.pi/extensions/worktree-guard/index.ts:144-160`,
  `blockReason` at :67), and `worktree-prep.sh` symlinks it (CONTRIBUTING.md:30-31, 44-46).
- Provenance of the `7%`: measured in a **throwaway worktree at tree `103a774` with worktree-local
  deps, deleted after** (`.development/investigations/complexity-crap-2026-11-02.md:20-25`). HEAD is
  `a67e9a3`. The number describes a different tree and is not reproducible from the repo.
- **Fix:** drop the numeric coverage bar. Replace with (i) an enumerated branch checklist derived from
  the source (see *Acceptance amendment*) and (ii) a named mutation list with the killing case for each.
  If a coverage number is still wanted in the PR description, it must carry the command, the tool
  versions, and the commit it was measured on — as evidence, not as a gate.

**B2 — the required escape-branch mutation kill is invisible to end-offset assertions.**
The issue frames the function as *"returning the END OFFSET"* and requires *"a deliberate mutation of an
escape branch fails at least one test"*. The escape branches live in `readJsonStringAt`
(`src/session-manager.ts:642-668`), and the interesting one changes **only `value`**:
```
text = '"a\\\\"'   (i.e. "a\\")
base : {"value":"a\\","end":5}     M1 (delete `escaped = false;` at :646) : {"value":"a\\\\\"","end":5}
skipJsonValue(text,0): base 5, M1 5      <-- identical
```
Measured over the whole 100-case matrix, **zero** cases changed their end/index observable under M1 or
under M8 (`raw.slice(1,-1)` → `raw` at :661). Both are killed only by asserting `value`.
- Note also that the issue's own example, `\\` in isolation, does **not** kill M1: `"a\\b"` → end 6 in
  base *and* in M1. The discriminating case is an escaped backslash **immediately before the closing
  quote** (`"a\\"`), and it must be asserted on the pair.
- **Fix:** the acceptance must read *"assert the `{value, end}` pair returned by `readJsonStringAt`"*,
  and must name M1's killer (`"a\\"` → `{value:'a\\', end:5}`) and M8's (`"a\\qb"` → `{value:'a\\qb', end:6}`).

**B3 — "assert the defined behaviour, not an accident" is unactionable: there is no defined behaviour.**
The whole contract on record is one JSDoc line, `src/session-manager.ts:671` — *"Skip one JSON value
(scalar, object, or array) without parsing it."* Nothing in the source, ARCHITECTURE.md or an ADR states
what happens on malformed input. And `JSON.parse` supplies no oracle for most of the issue's own list:
**18 of 45** `skipJsonValue` cases in the matrix make `JSON.parse(text.slice(0,end))` throw — every
unterminated case, every mismatched-bracket case, the BOM/NBSP cases, `]`-terminated scalars, `NaN`,
`nul`, `abc]def`. For those the expectation must be hand-written, which means a human must decide it.
- **Fix:** record five one-line decisions in the issue *before* tests are written (D1-D5 below). Four
  can be pinned as-is; two need an actual choice.

### MAJOR

**M1 — the oracle is mis-specified: `JSON.parse` returns a value, the function returns an offset.**
Measured counterexamples to the two naive formulations:
- `end === text.length` fails on **12/45** skip cases, including valid JSON: `'[1,2] '` → 5,
  `'{"a":1} xyz'` → 7, `'true,'` → 4.
- minimality (`JSON.parse(text.slice(start,end-1))` must throw) holds for strings and containers but
  **fails for the scalar branch**: `'12,'` → end 2 and `JSON.parse('1')` succeeds; `'1e999'` → 5 and
  `'1e99'` parses; `' 42,'` → 3 and `' 4'` throws but `' 42'`-1 does not.
- **Sound form** (use this): `JSON.parse(text.slice(start,end))` succeeds and deep-equals the expected
  value **and** `end === text.length || /[\s,}\]]/.test(text[end])`. Exactness for the scalar branch
  cannot come from `JSON.parse` at all — it comes from the documented terminator rule (D4).

**M2 — whitespace: the impl's alphabet is `\s`, JSON's is four chars, and `JSON.parse` is the wrong oracle.**
`skipWhitespace` (`src/session-manager.ts:635-639`) uses `/\s/`. Measured: NBSP → 1, BOM → 1,
U+2028 → 1, VTAB → 1, U+3000 → 1 — while `JSON.parse('\u00a0{}')` and `JSON.parse('\ufeff{}')`
**both throw SyntaxError**. Any "compare against `JSON.parse`" test on the whitespace class is unsound
by construction; the divergence also reaches `skipJsonValue` (`'{\u00a0"a":1}'` → 8, JSON.parse throws).
This is load-bearing, not pedantic: `readAgentIdentity` (:766-790) returns `null` when `status` is
missing, so a BOM-prefixed record read with JSON's strict alphabet **silently disappears from retry
lineage** — the exact harm the issue is about. Measured: mutant M11 (`\s` → `[ \t\n\r]`) is killed only
by the NBSP/BOM/U+2028/VTAB/U+3000 cases and by a BOM-prefixed record at scan level.
- **Fix:** decide the alphabet (D2), then pin it with the five divergent characters, hand-written
  expectations, explicitly *not* against `JSON.parse`.

**M3 — missing input classes.** Measured, with the mutant each one kills:

| missing class | input → measured | why it matters |
|---|---|---|
| escaped backslash before the closing quote | `'"a\\\\"'` → `{value:'a\\',end:5}` | the **only** kill for M1 (B2) |
| escape inside a container **followed by trailing content** | `'{"a":"\\n"} xyz'` → 10 (M4 → 14) | the only skip-level kill for M4 (`escaped` never cleared, :681). `'{"a":"x\\ty","b":2}'` → 18 in base **and** M4: without trailing content the mutant is invisible |
| escaped quote followed by a brace inside a string | `'{"a":"\\"}","b":2}'` → 17 (M3 → 9) | the only kill for M3 (`escaped = true` disarmed, :682) |
| braces/commas/brackets inside strings | `'{"a":"} , {" }'` → 14; `'[{"a":"]"}]'` → 11 | kills M14 (`inString` never armed, :685); the issue lists "escapes" and "containers" but never the composite |
| `]` as a scalar terminator | `'1]'` → 2 vs `'1,'` → 1 vs `'1}'` → 1 | real asymmetry; pinning it freezes a quirk (M7, the "obvious fix", is killed by exactly these) → needs D4 |
| mismatched brackets | `'[1}'` → 3, `'{"a":1]'` → 7, `'{"a":[1}]}'` → 9 | depth counting is bracket-type-agnostic → needs D3 |
| empty containers | `'{}'` → 2, `'[]'` → 2 | the issue names empty *strings* only |
| the JSON.parse fallback's value/end asymmetry | `'"a\\qb"'` → `{value:'a\\qb', end:6}` | `end` is always right, `value` is best-effort raw → D5; kills M8 |

| out-of-contract `start` / zero progress | `skip(t,99)` → 99; `'}'` → 0; `','` → 0; `''` → 0 | invariant "returns a value in `[start, text.length]`, never throws" is unstated; the caller's termination depends on it (m2) |
| non-finite / signed zero | `'1e999'` → `Infinity`; `'-0'` → `-0` | `JSON.stringify(Infinity)` → `null`: a round-trip property oracle silently asserts nonsense unless these are excluded |
| **precondition**: `start` is the value's first char | `' 42,'` → 3 (leading ws absorbed); `'\ufeff{}'` → 2 (BOM treated as a scalar!) | the caller already skipped whitespace (:738 `i = skipWhitespace(text, i + 1)`). Tests must not pin out-of-contract starts as if they were behaviour |
| `\/` (listed by the issue) | `'"a\\/b"'` → `{value:'a/b',end:6}` | listed but unremarkable — it kills nothing. Keep it, do not count it |

**M4 — scanner-only tests do not prove the named regression mode. Measured.**
Mutant M17 replaces the caller's nested-payload skip (`src/session-manager.ts:756`, `i = skipJsonValue(text, i)`
→ `i += 1`) — i.e. precisely *"a scanner bug silently mis-parses persisted transcripts"*. It is killed by
**five scan-level cases and by zero `skipJsonValue` cases**: `t02` decoy identity key nested after the real
one, `t03` decoy `attempt`, `t04` CRLF record, `t13` unterminated nested string, `t14` array value.
Mutant M18 (the *wanted*-key container branch, :745-747 → `i += 1`) is killed by exactly one case: a wanted
key whose value is an object. Neither branch is in the issue's plan.
Corroborating the gap in the committed suite: `grep -rln "findRetryLineage" src/__tests__` → **empty**;
the lineage suite's `writeAgent` fixture (`src/__tests__/get-subagent-result-lineage.test.ts:130-153`)
writes **flat** records via `JSON.stringify` — no `result.messages`, no braces or escaped quotes inside a
skipped payload — and its one malformed case (:315-331) is a *truncated* record, which never enters the
container branch. So the branch the scanner exists for (:486-489, *"extracts just the identity fields with
a top-level scanner instead of JSON-parsing result.messages"*) has no deliberate coverage at any level.
- **Fix:** the plan must include ≥5 `scanTopLevelScalars` cases (t02, t03, t06, t13, t14 below) and ≥1
  `findRetryLineage`-level case through `__setStorageDir`.

**M5 — "deep nesting (bounded)" has no falsifier.**
The scanner is iterative; measured on the real source: depth 1 000 → 0 ms, depth 20 000 → 1 ms,
depth 200 000 → 2 ms with `end === text.length`, no throw, no stack growth. `JSON.parse` also survives
depth 100 000 on Node v24.14.1. There is no bound in the code and no behaviour that can fail, so the
bullet as written is decorative — a vacuous pass.
- **Fix:** state the property instead of a bound: *"no recursion: `end === text.length` and no throw at
  depth 10 000 and on a ~200 KB nested record"*. Falsifier: rewrite the loop as recursion → `RangeError`.
  Measured on a realistic 220 073-byte record (`result.messages` × 2000): scan 1 ms, identity fields intact.

### MINOR

**m1 — property loop: worth it, but constrained.** `fast-check` is absent from `package.json`
devDependencies (pi-*, jiti, typebox, typescript, vitest) and ADR 0021 forecloses new CI deps, so a
seeded hand-rolled loop over `JSON.stringify` round-trips is the only option. There is **no precedent**
for one in this suite (`grep -rln "fast-check\|fc.assert\|Math.random" src/__tests__/*.ts` → empty), so
it must be deterministic (fixed seed, fixed iteration count) or it becomes a flaky gate; and it must
exclude non-finite/`-0` (M3). Its oracle is the M1 two-sided prefix form, restricted to strings and
containers — where minimality actually holds.

**m2 — `if (i <= keyStart) break;` (`src/session-manager.ts:759`) survived all 13 mutants and all 100
cases.** Arithmetic suggests it is unreachable: after the `:` step `i ≥ keyStart+3`, and both readers are
monotone. It is nevertheless the only thing between the scanner's zero-progress returns (`skip('}')===0`,
`skip(',')===0`) and an infinite loop, so keep one termination test (`'{"id":"x","a":,}'`,
`'{"id":"x","b":'` — both measured to terminate). Out of #428's stated scope; if a coverage number is
ever reported for the *file*, say explicitly that this branch is defensive and excluded.

**m3 — "trailing garbage" is not malformed input for this function.** `'{"a":1} xyz'` → 7 is correct
behaviour: the function returns the end of the *first* value and ignores the rest. The assertion is
`end === 7`, **not** a throw. Listed under "malformed/truncated" in the issue, an implementer will
reasonably write `expect(...).toThrow()` and the case becomes a false pin.

**m4 — the issue's scope sentence is narrower than its own acceptance.** The required escape kill (B2)
lives in `readJsonStringAt`; the regression mode (M4) lives in `scanTopLevelScalars`. Widen the scope to
"the three-function shallow reader (`skipWhitespace`/`readJsonStringAt`/`skipJsonValue`) plus its caller
`scanTopLevelScalars`", and state non-goals: **no extraction, no refactor** (ADR 0021 §2 assigns the
behaviour-preserving refactor slot to #430/`execute`), **no new dependency, no coverage CI step**.

## Decisions the issue must record before tests are written

| # | question | measured current behaviour | recommendation |
|---|---|---|---|
| **D1** | unterminated string / container | `'{"a": [1,2'` → 10 = `text.length`; `'"abc'` → `{value:'abc',end:4}` | **pin as-is.** It is the "corrupt record is skipped, never throws" contract, and it is already corroborated end-to-end: a truncated record yields no `status` → `readAgentIdentity` returns `null` (lineage test :315-331 asserts the record is skipped) |
| **D2** | whitespace alphabet: `\s` or JSON's four chars | `\s` — NBSP/BOM/U+2028/VTAB/U+3000 all consumed; `JSON.parse` rejects them | **keep `\s`, document it.** Narrowing it would drop BOM-prefixed records from lineage silently (M2). Falsifier: M11 must be killed |
| **D3** | bracket-type-agnostic depth counting | `'{"a":[1}]}'` → 9, `'[1}'` → 3 | **pin as-is + document** ("balanced-count, type-agnostic; strictness is `JSON.parse`'s job"). A strict stack would raise the complexity the CRAP finding already flagged. Unreachable on valid JSON either way |
| **D4** | scalar branch stops at `,`/`}` but **not** `]` | `'1]'` → 2, `']'` → 1 | **document the terminator rule as the contract** ("scan to the first `,`, `}` or EOF") and pin it. Both call sites are an object's top-level value position (:748, :756), so `]` is unreachable on valid input — "fixing" it (M7) changes nothing in production but breaks the pin. If the maintainer prefers the fix, that is a **separate behaviour issue**, not a test issue |
| **D5** | `readJsonStringAt`'s fallback returns a **raw** value with a correct `end` | `'"a\\qb"'` → `{value:'a\\qb',end:6}` (backslash kept) | **document as best-effort** and pin the consequence, not just the value: an invalid escape inside `"id"` yields a value `assertSafeAgentId` rejects (`src/sanitize.ts:137-141`, UUID-only) → `readAgentIdentity` returns `null` → the record leaves lineage. One test should assert that drop so the consequence is pinned rather than assumed |
